# Alternative data sources for CollisionGuard

The subsequent [source audit and verdicts](data-source-audit.md) includes complete-tree replay and supersedes the preliminary checks below for current source decisions.

Research date: 8 November 2026 UTC, corresponding to 7 November in America/Phoenix. These probes followed the pilot's 04:39 UTC sample freeze. Three focused searches examined collaborative benchmarks, single-agent trajectory datasets, and real GitHub workflow records. The coordinator checked selected records and patch applicability. This is a bounded search, not proof that all public sources have been found. No agents were run to generate training data, no model was trained, and no full dataset or repository was downloaded.

## Recommendation

Audit existing benchmark releases before building our own dataset. ParallACT and the original CooperBench trajectories contain much more relevant public evidence than the AIDev snapshots inspected in the pilot. One sample from each includes two distinct task inputs and two agent patches. Both pairs' patches passed limited applicability checks against files from their stated or candidate base. Neither source is yet certified for direct training use.

Keep two study settings distinct. Natural historical dispatch needs evidence of what was known before both real executions started. A controlled benchmark can instead freeze two task inputs and a starting repository version through its execution design. The latter may support the pre-execution prediction question, but does not establish naturally occurring concurrency, ready times, or real-world scheduling benefit. Using it would require a separately documented evaluation design; it does not retroactively pass the AIDev pilot gate.

## ParallACT

The [paper](https://arxiv.org/abs/2611.00314) and [project page](https://lingyunxiao18.github.io/ParallACT/) describe paired requests on a common codebase, with parallel-unaware and communication conditions. The benchmark deliberately emphasizes complementary and contradictory tasks rather than ordinary independent work. Its reported coordination results are not conflict-prediction results.

At repository revision `c212deb174fbc8980212cc1bde5b3f047941f332`, the [NodeBB instance](https://github.com/rm206/ParallACT_data_and_code/blob/c212deb174fbc8980212cc1bde5b3f047941f332/dataset/v1/seeds/contradictory/instance_NodeBB__NodeBB-4327a09d76f10a79109da9d91c22120428d3bdb9-vnan.json) supplies `repo`, `base_commit`, `agentA_problem_statement`, and `agentB_problem_statement`. Its `agentA_solution` and `agentB_solution` are reference patches and must not be substituted for agent outputs.

The actual [parallel-unaware run export](https://lingyunxiao18.github.io/ParallACT/data/runs/api--claude_code--opus-4.8/v1/contradictory/instance_NodeBB__NodeBB-4327a09d76f10a79109da9d91c22120428d3bdb9-vnan/parallel_unaware.json.gz) contains both `turns[].prompt` strings, `started_at`, per-agent usage, and nonempty `outputs.A` and `outputs.B` diffs. Its `traj` entries are counts, not full trajectories inspected in this check. The exported Git-merge status says conflict; we did not reproduce that label.

The inspected prompts do not identify a partner and the run's `messages` list is empty. Its 86-second wall time is shorter than the two turns' combined 120.201 seconds, which is consistent with parallel execution. These are positive checks of the exported unaware condition, not proof of the exact runner revision or all original execution state.

The pinned [workspace source](https://github.com/rm206/ParallACT_data_and_code/blob/c212deb174fbc8980212cc1bde5b3f047941f332/running_instances/common/engine/workspace.py) checks out the declared base and diffs against it. The [orchestrator](https://github.com/rm206/ParallACT_data_and_code/blob/c212deb174fbc8980212cc1bde5b3f047941f332/running_instances/common/engine/orchestrator.py) creates separate workspaces and constructs each prompt before invoking its runner. This supports the intended design, but the inspected export does not identify the exact code revision that produced the September run. It does not prove a common historical dispatch instant by itself.

The coordinator fetched only the three touched NodeBB files at `754965b572f33bfd864e98e4805e1182c1960080` and ran `git apply --check -` separately for each output against that unchanged subset. Both exited 0; base-file transfer was 19,853 bytes. This checks subset applicability only, not full-tree merging or functional correctness. The seed response hash was `c62f9dc0f0a5da0434cf79271a86a8c113dd85dfb228b545c67a65e6470d0d82`; the compressed run export hash was `bda5acf0c99b41a689eaac755529e76a47c645da9dc3e716c4b8f5018c02d8b5`.

After review, the coordinator also compared the patches' original Git blob prefixes with those base files. Mongo `e6911a09b2`, PostgreSQL `c6f46e1e74`, and Redis `276ada4a05` all matched their fetched contents. Each exported prompt contains its corresponding seed task statement exactly once, with 146 additional wrapper characters. These checks strengthen file-level consistency and the task-to-run text association; they still do not identify the original full checkout or independently reproduce the merge outcome.

The explorer URL is mutable. Preserve checked bytes and establish run provenance before importing. This search did not establish reuse terms; that does not mean reuse is prohibited. Check the dataset terms and underlying NodeBB license. Selection by interaction family can make classification artificially easy. Keep related seeds, generated variants and repeated runs together when splitting. Predictors must exclude `family`, `shared_artifact`, `mutex_type`, `natural_language_explanation`, `diversity_mechanism`, reference solutions, reconciliation patches and explanations, test patches, fail/pass lists, and all evaluator outputs. Restrict model inputs to separately audited pre-execution task inputs and allowed repository information.

## CooperBench

The original [CooperBench/trajectories release](https://huggingface.co/datasets/CooperBench/trajectories/tree/906bc2f62325eb6f8ccb4cf221e63df051cb3c99/coop/dottxt_ai_outlines_task/task1371/feature1_feature2) is a better lead than the converted team-coop sample initially inspected. The pinned directory contains `execution_traj_claude_k1_feature1.json`, `execution_traj_claude_k1_feature2.json`, their separate `patch_claude_k1_featureN.patch` files, conversation records and a merge report. Its README declares MIT; underlying source-code terms still require checking.

The coordinator read both complete event lists. Each has an initial `source: user` message, before that agent's subsequent actions, describing a distinct feature. One adds custom prompt filters and the other a global filter registry. These are actual execution inputs, but they already include coordinated implementation plans, partner-feature references, a `Files Modified` list naming `outlines/prompts.py`, and line ranges. The agents then exchanged messages that appear as later `source: user` events. These are confirmed plan-sharing, communicating-agent outputs and cannot be used as unaware-agent labels. An importer must distinguish the first input event from later messages. Predicting file overlap from an input that names the target file would be trivial. Removing those hints afterward would not make the original outputs equivalent to runs without hints.

The first user timestamps are 2025-10-31 21:59:38.439997 and 21:59:30.242826, without explicit timezone offsets. The release also has gpt5, minimax, qwen and qwen_coder runs and separate plan files for this same feature pair. These are repeated runs, not independent task pairs, and belong in the same split group. Some conversation files are nearly empty, so check completeness per run rather than assuming it from the directory structure.

Neither inspected trace exposed an explicit starting commit. A [pinned task Dockerfile](https://huggingface.co/datasets/CooperBench/cooperbench-dataset/blob/b612b1a35af722751454813d9e5a7888f065fc9e/dottxt_ai_outlines_task/task1371/Dockerfile) specifies `7149a5e613b9c2bb3c2ed3ee5b7c9228772504b1`. The two patches both modify `outlines/prompts.py`. That file fetched at the candidate base has Git blob ID `86519adaf45b13172814199c088c22755f389b9b`, matching both patches' original index prefixes. Each patch independently passed `git apply --check` on that file. Whitespace warnings occurred, but both checks exited 0. This supports file-level base consistency, not proof of the entire original checkout or a full merge label.

The exported merge report's evaluator log also shows `HEAD is now at 7149a5e6`, corroborating the base during evaluation rather than during the original agent execution. Its clean merge report is not a trusted label: the merge diff is empty, tests failed, and both agent patches add overlapping registry code. Recompute labels with a defined Git merge procedure; do not substitute evaluation success or the exported status.

The two trace hashes are `28e9b04381029a434ab333727b53fb1bca6070ad4bf834a09dce35fc7341efe7` and `b82228234575885e2ccbc3f3bcd20a7b94119fc93e0e79d03c38179ed3d3a507`; patch hashes are `f2ec40df4a9131ae9113c801ed3fda20e76d950850b0e5871b7dac064164b78d` and `73a21fa54594fb5b844e7bf8e6c75fa8c5a4bd1bba8adc5d5d041d40d221a942`. Raw traces totaled 1,365,624 bytes.

The initial [team-coop sample](https://huggingface.co/datasets/CooperBench/team-coop/tree/7348f4baa12d53c2c2d537943e7846ff8587e411/cmp-full-team/coop/dottxt_ai_outlines_task/1371/f1_f2) has reconstructed conversations and a lead whose task includes integrating the other patch. Do not use an integrated output as an independent task patch. The separate [team-trajectories card](https://huggingface.co/datasets/CooperBench/team-trajectories) advertises original archives worth inspecting if needed. The benchmark's gold `feature.patch` files remain distinct from all these agent outputs.

## Single-agent trajectories

[Nebius SWE-rebench OpenHands trajectories](https://huggingface.co/datasets/nebius/SWE-rebench-openhands-trajectories) expose `instance_id`, `repo`, an ordered `trajectory`, `model_patch`, `exit_status`, and evaluation fields. The researcher saw a truncated viewer sample; the coordinator then retrieved an untruncated single row through the [rows endpoint](https://datasets-server.huggingface.co/rows?dataset=nebius%2FSWE-rebench-openhands-trajectories&config=default&split=train&offset=0&length=1). For `PlasmaFAIR__sdf-xarray-24`, the retained probe records a user message, no truncated cells, and a nonempty model patch. Its response SHA-256 is `54270287b38d6031c5c3548bf0bfcf63b6267eacbf322ffca3c3b2a07239cf75`. The coordinator's terminal output also recorded the first user-message preview and a 395,268-byte response, but the raw response and event-order details were not retained. Confirm exact initial-input ordering during an import audit rather than treating the probe summary as complete provenance.

The attempted exact-ID join to [SWE-rebench-V2](https://huggingface.co/datasets/nebius/SWE-rebench-V2) returned HTTP 500 with a temporary Hub authentication-check error. It did not establish whether that task exists there, which task release matches the trace, or its base commit. A separately inspected V2 task row had a base commit but a different instance ID and is not a verified join. Next resolve the trace's correct task catalog, check its input equality and base, and find two distinct tasks at a compatible base. Multiple trajectories for the same issue are alternative attempts, not a task pair. None was verified in this search.

Other inspected samples are useful leads rather than ready pairs:

- [Nebius SWE-agent trajectories](https://huggingface.co/datasets/nebius/SWE-agent-trajectories) contain repeated attempts for `AnalogJ__lexicon-336`, ordered messages and generated patches. Task/base joins remain needed. The current viewer and pinned README showed differing license declarations, so resolve those before reuse.
- [SWE-Gym sampled traces](https://huggingface.co/datasets/SWE-Gym/OpenHands-Sampled-Trajectories) include `getmoto__moto-5321`, whose inspected run has an empty generation. Join to [task metadata](https://huggingface.co/datasets/SWE-Gym/SWE-Gym) and retain incomplete outputs explicitly.
- [SWE-smith trajectories](https://huggingface.co/datasets/SWE-bench/SWE-smith-trajectories) include ordered inputs and patches for synthetic bug-injection tasks. Generated task bases must be checked before pairing; a shared repository name is insufficient.
- [R2E-Gym tasks](https://huggingface.co/datasets/R2E-Gym/R2E-Gym-V1) and [SFT traces](https://huggingface.co/datasets/R2E-Gym/R2EGym-SFT-Trajectories) were inspected, but a stable trace-to-task/base join was not established. Do not infer it from generated issue text alone.
- [AsynCodeBench](https://github.com/KaituoZhang/AsynCodeBench/tree/2a639b049f249e79eb2031876bc06a110be9ac3a) has task/base manifests and an asynchronous harness. No reusable paired run was inspected, so it remains a possible source for new runs.

## Natural workflow records

[GitHub Agentic Workflows](https://github.github.com/gh-aw/reference/artifacts/) documents prompt and agent-output artifacts. The public `github/gh-aw` run `33578395023` exposed run times, workflow head and job metadata. The sampled agent job had both repository and PR-branch checkout steps, so workflow `head_sha` alone does not establish the agent's checkout. An anonymous small-artifact download returned 401; a job-log request returned 403. Contents were not inspected. These are case-specific access results, not proof that every public log requires credentials. Artifact retention also limits long-term availability. [Workflow run](https://github.com/github/gh-aw/actions/runs/33578395023), [Actions API](https://docs.github.com/en/rest/actions/workflow-runs)

Thus a published trailer does not establish an accessible original prompt. No session contents or prompt-to-code join was inspected. [GitHub session documentation](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/manage-and-track-agents)

Owner-published original run artifacts could still help. Public PR metadata, workflow timestamps, commit messages, or output issues alone do not supply the missing original instructions and checkout provenance. This search did not find a verified natural-history pair with the required complete records.

## Next decision

First audit a small sample of existing ParallACT parallel-unaware records. Treat original CooperBench outputs as a separate plan-sharing, communicating condition rather than a replacement unaware-agent dataset. Establish usable terms, actual initial inputs, common base, output ownership, interaction condition, immutable source bytes, and reproducible full Git labels. Keep benchmark outcomes distinct from historical dispatch claims and keep the listed outcome-derived metadata out of prediction features.

If one source passes, build an importer and labels from existing outputs before paying for new agents. Measure coverage, class mix and independent task/repository counts before promising a training set. A convenience sample passing import checks is not a representative final evaluation set. CooperBench communication settings and ParallACT constructed task families need separate analysis.

If neither provides enough usable examples, adapt existing task definitions and run a small controlled collection with both prompts and exact initial snapshot captured before either launch, isolated task outputs, complete run records, finite budgets and a fixed evaluator. New generation is a fallback, not the conclusion of an unsuccessful AIDev snapshot audit.
