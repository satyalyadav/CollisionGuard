# SWE-rebench task and base verification

Verified on 15 November 2026 UTC. SWE-rebench/OpenHands should replace AgentLogs as the immediate source to audit for expansion. A metadata join establishes 144 candidate unordered task pairs in 121 same-base groups across 76 repositories. These counts establish candidate coverage, not valid initial execution trees, complete output coverage for every pair, or usable merge labels. No new merge labels or model results were produced.

## Recommendation and checks

Run a bounded SWE-rebench import audit across a predeclared set of new repositories. Require exact task/prompt matches, separate nonempty agent outputs, source-version consistency, and verified full starting-tree compatibility before full-tree replay. Resolve task-specific image and test setup first. Keep every attempted candidate and exclusion in the denominator and keep related tasks in one repository group. This is the strongest next collection route identified here; it is not yet a replacement training or final-test dataset. The separate [AgentLogs verification](agentlogs-verification-2026-11.md) established no qualifying pair in its small sample and recommends lowering that source's immediate priority.

Commands used `timeout -k 5s` wrappers for the saved `fetch.py`, `parquet_probe.py`, `project_tasks.py`, and `project_traces.py` scripts in the ignored evidence directory. Network scripts used at most two I/O workers, 30- or 45-second request timeouts, and response caps. DuckDB used one worker and a 128 MiB memory limit for local column projection. The accounted total is 107 requests and 6,891,652 received response-body bytes. This excludes protocol overhead, redirect bodies not read by the client, and potentially buffered bytes before errors. No source code, agent commands, builds, tests, or model training were executed. The first root attempt was interrupted before creating its workspace; process inspection confirmed no surviving root verification job before retrying.

It does not verify original full starting trees, run merge replay, or validate every candidate patch.
