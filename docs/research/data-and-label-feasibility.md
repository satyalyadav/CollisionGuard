# CollisionGuard data and label feasibility

Research date: 2026-11-07. Scope: the [original proposal](../proposal/original-proposal.md). No full dataset or repository was downloaded. Sizes below are decimal bytes as reported by source APIs, not memory requirements.

## Decision

**Conditional go for a small provenance and replay pilot; no-go for claiming a leakage-safe pre-execution training set yet.** AIDev v5 exposes the required kinds of links and commits, and Git can produce a textual merge label for accessible heads. The sources do not establish that linked issue text is the version available before either agent began, or that the recorded PR heads and bases represent independent work at a common decision time. Measure those properties on actual pairs before committing to the proposed model or scheduling evaluation. Neither the published replay sample nor CooperBench proves the availability of suitable AIDev training examples.

## AIDev versions and fields

The [v5 card](https://huggingface.co/datasets/hao-li/AIDev-7.6M) reports 7,685,281 agent PRs in 961,168 repositories, six agent categories, and a 2026-03-31 creation cutoff. These are overall source totals, not usable issue-linked pairs. AIDev-pop selects repositories with more than 100 stars and adds PR details, issue links and other tables; that selection excludes less popular and private repositories. The [AIDev paper](https://arxiv.org/abs/2602.09185) describes the dataset and its linked artifacts, not a validated CollisionGuard label set. The [current card](https://huggingface.co/datasets/hao-li/AIDev) records a fix for unpaginated PR subresources in October 2026. Re-fetched events may postdate the original cutoff and file-level commit details can still omit commits after the first 30. GitHub does not supply all large patches. Filter event times and audit missingness; an absent patch is not an unmodified file.

Pin the actual commit, not only `main` or a mutable tag. The [v5 revision API](https://huggingface.co/api/datasets/hao-li/AIDev/revision/v5) returned `b8dc67df93e7c11f6f20c84129db7232eb1ec253`; the separately hosted [7.6M repository](https://huggingface.co/api/datasets/hao-li/AIDev-7.6M) returned `bebd85fceee94d57e8813320e479682e00a292b7`. The card says the v5 files match, but pin one repository and verify file hashes rather than assume the two commit identifiers match. The [v4 tree](https://huggingface.co/datasets/hao-li/AIDev/tree/v4) identifies AIDev-2.7M, cutoff November 2025, with revision `a1a0e853682c2396474538c2026930802505c1d5` according to its [revision API](https://huggingface.co/api/datasets/hao-li/AIDev/revision/v4). Its tree lacks `issue`, `related_issue` and `pr_timeline` files, and its PR subresources are subject to the 30-item truncation. Thus v4 is not a drop-in fallback for the stated issue-linked pipeline; a separate, audited historical issue source would be needed. The 2.7M label is rounded, not a verified exact v4 total.

The v5 dataset viewer exposes `pull_request` fields `id`, `number`, `body`, `agent`, `created_at`, `closed_at`, `merged_at`, `repo_id` and URLs; `related_issue` has `pr_id`, `issue_id`, `source`; `issue` has `id`, `number`, `title`, `body`, `created_at`, `closed_at` and `html_url`; and `pr_commits` has `sha`, `pr_id`, `author`, `committer`, `message`. Join `pull_request.id = related_issue.pr_id` and `related_issue.issue_id = issue.id`, retaining the relationship source and handling multiple issues per PR. See the dataset-server schemas for [pull requests](https://datasets-server.huggingface.co/first-rows?dataset=hao-li%2FAIDev-7.6M&config=pull_request&split=train), [links](https://datasets-server.huggingface.co/first-rows?dataset=hao-li%2FAIDev-7.6M&config=related_issue&split=train), [issues](https://datasets-server.huggingface.co/first-rows?dataset=hao-li%2FAIDev-7.6M&config=issue&split=train), and [commits](https://datasets-server.huggingface.co/first-rows?dataset=hao-li%2FAIDev-7.6M&config=pr_commits&split=train). These inspected schemas do not provide issue edit history, a link-creation timestamp, PR base SHA, or an explicit head SHA and start time. Commit membership alone does not prove which SHA was the relevant head. Check raw Git objects and independently captured metadata.

Issue `created_at` only proves the issue existed then; current `title` and `body` may have been edited later, and a link can be added after work starts. A PR description and even an agent label derived from a later PR signature are not automatically known at task readiness. Require an independently timestamped original issue revision, and evidence that the task-to-issue association and agent assignment were known at the prediction cutoff. If those cannot be established, exclude the feature or mark it unknown. PR-open intervals are a retrospective co-activity proxy, not evidence of exact coding-start or task-ready time.

## Cost and access

The [v5 file listing API](https://huggingface.co/api/datasets/hao-li/AIDev/tree/v5?recursive=false&expand=true) reports approximately 22.4 GB for all repository files. `all_pull_request.parquet` is 6.73 GB and `pr_commit_details.parquet` 12.45 GB. The smaller pop `pull_request`, `issue`, `related_issue`, `pr_commits` and `repository` files total about 0.78 GB; `pr_timeline` adds 1.10 GB. These are file transfer/storage sizes, not peak RAM or Git object costs. The [loading guidance](https://huggingface.co/datasets/hao-li/AIDev-7.6M) warns against blindly loading large tables into pandas. The v4 tree reports 3.11 GB overall, including 1.33 GB of commit details. Use column projection, row-group streaming or small server-side samples, record byte limits, and fetch Git objects only for the pilot. Test whether the selected access method actually supports filtered reads before budgeting network usage.

The dataset card declares CC BY 4.0, but [its license section](https://huggingface.co/datasets/hao-li/AIDev#license) explicitly preserves each source repository's own license for its contents and patches. Check source licenses and permitted reuse of issue text and code before redistribution; dataset attribution alone does not clear every underlying artifact.

## Historical replay and provenance

The [replication paper](https://arxiv.org/html/2607.04697) reports 747 sampled co-active pairs, one per repository: 625 same-agent and 122 cross-agent. Of 716 evaluable pairs, 167 conflict and 549 merge cleanly. The same-agent rate is 119/601 and cross-agent 48/115; 25 lacked fetched PR refs and six lacked an accessible merge base. The 23.3% pooled sample rate is not a population prevalence: the study sampled strata deliberately, while the paper reports that same-agent pairs account for 99.5% of co-activity. Results describe open-source AIDev-pop under its historical mining criteria, not all projects or future tasks.

The [official replication README](https://github.com/Quantum535/concurrent-agentic-prs-replication) documents repo, PR numbers, agents, labels, conflict paths and types in its 747-row CSV. It describes fetching live `refs/pull/N/head`, finding `git merge-base`, and running `git merge-tree --write-tree`. Its published CSV schema does not list the fetched head SHAs or merge-base SHA, so the rows alone cannot establish immutable replay inputs; live refs may change or disappear. Inference: later heads can contain review changes, upstream merges or other post-decision information. A replay can describe integration of those heads without proving conflicts between initial independent agent outputs.

The [Zenodo record API](https://zenodo.org/api/records/21186464) resolved even though the DOI page failed in the web fetch. It reports a 302,847-byte ZIP, CC BY 4.0, and MD5 `59a99c9cf58793957806a7fa5e712f8f`. The accessible [GitHub mirror](https://github.com/Quantum535/concurrent-agentic-prs-replication) identifies the same package; its main commit was `3f5970588c412b43b50ddb67a68b38ecffdca70d` at inspection. The archive and mirror were not compared byte-for-byte. Treat the sample as a label-method reference until exact pair and repository overlap with training and tuning is removed and input provenance is checked.

## CooperBench external evaluation

The [paper](https://arxiv.org/html/2601.13295) describes 652 feature pairs across 12 repositories and 199 features. Features are curated around a common base, including synthetic adjacent features, so they are not independently sampled historical agent tasks. Its appendix inconsistently describes 34 PRs and 52 task sets; the [current official dataset README](https://github.com/cooperbench/CooperBench/blob/main/dataset/README.md) lists 30 task directories by repository. Pin a matched dataset and harness revision and count the actual manifest instead of reconciling these claims by assumption. The inspected [repository commit](https://api.github.com/repos/cooperbench/CooperBench/commits/main) was `63b9d44d9f39a02fccf5bf0052db48a917a011fd`; check its release and matching data before use.

The official README says 499 of the 652 pairs conflict when their gold feature patches are merged, and provides feature descriptions, feature patches, tests, and a combined resolved patch. That is a gold-patch conflict outcome, not necessarily the conflict outcome of actual agent-produced heads. Generate and verify labels with the same pinned merge procedure used for AIDev, and report it as a curated distribution-shift test, not an estimate of historical conflict prevalence. Avoid training on its gold patches or conflict report. The README labels the dataset MIT, while the paper lists underlying repository licenses; check both before reuse. Sizes of the chosen pinned subset, container images and Git objects were not established here. Running the full harness is not required for the text-label pilot.

## Minimum pilot and data contract

Start with a fixed, documented sample of 20 candidate pairs across at least five repositories, selected before examining labels. Include both same-agent and cross-agent pairs when available. This is a pipeline check, not enough for model-performance claims. Preserve every attempted pair and exclusion reason, including missing issues, unverified text time, unavailable heads, unrelated histories and replay errors. Manually audit the source and timing of every retained task description. Budget and report bytes fetched and time spent; stop before expanding if provenance recovery requires an impractical amount of data.

One pair record should contain: dataset repository, immutable revision and file hashes; stable repo and PR IDs; issue IDs, link source and evidence of link time; task text, revision/source and proof it predates the decision cutoff; the cutoff definition and evidence for agent identity; base repository SHA at cutoff; each selected head SHA, selection timestamp and ancestry; retrospective activity window kept outside features; and repository license. Record Git version, merge command and options, merge base SHA, exit status, conflict paths and label `CLEAN`, `CONFLICT` or a specific `UNAVAILABLE/ERROR` reason. Store labels and post-execution files separately from prediction inputs. A shallow fetch failure is unavailable until deeper history resolves it, not a clean merge. Define treatment of merges, rebases, renames and multiple merge bases before labeling; do not silently replace a recorded head with a later live ref.

Proceed to dataset construction only if the pilot demonstrates reproducible clean and conflict labels, immutable accessible inputs, and verified pre-execution text and associations for a useful share of pairs across multiple repositories. Report counts and failure reasons before choosing a larger sample. No-go for the proposed leakage-safe claim if historical text or association timing cannot be proved, or if independent heads and a defensible base cannot be recovered. For model evaluation, additionally require enough independent repositories and both classes in each held-out evaluation split; group shared PRs and repositories together and keep any footprint predictor's training and tuning inside the training fold. If these gates fail, revise the research question to a clearly labeled retrospective proxy or collect prospective task snapshots.
