## Tasks, outputs and file supervision

The [upstream schema](https://github.com/rm206/ParallACT_data_and_code/blob/c212deb174fbc8980212cc1bde5b3f047941f332/README.md#L69) lists a repository, `base_commit`, two problem statements and reference solution diffs. The reference solutions are not agent outputs. For the twelve existing cases, the [release assessment](parallact-public-release.md#L37) reports that both task fields matched pinned seed fields and website run prompts under its stated normalization. The [association checks](../../scripts/parallact_collect.py#L155) require matching run identity, no messages, two turns, distinct assignments and separate nonempty outputs different from the reference solutions. Those checks support the recorded unaware condition; they do not independently prove execution isolation or the runner revision. The [existing audit](data-source-audit.md#L53) likewise limits its inference, and the [recovery ledger code](../../scripts/parallact_recovery.py#L282) records the execution and site revisions as unknown. None of these checks has been repeated for the fresh paths.

The existing twelve have verified reconstructed base trees and separately applied agent patches according to the [dataset guide](../../data/parallact-12/README.md#L20). In principle, comparing each verified agent tree to its common verified base can yield per-agent changed-file targets. This is conditional on retrieving and validating each fresh output and full base; metadata availability alone does not supply file targets. The public feature bundle explicitly has no file-prediction targets ([guide](../../data/parallact-12/README.md#L22)). A future protocol must specify treatment of renames, deletions, binary files, paths and failed or incomplete outputs, and keep resulting target paths out of pre-start predictors. This round did not inspect patches or derive file lists.
