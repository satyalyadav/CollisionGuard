# Data-source audit and verdict

Audit date: 8 November 2026 UTC. This gives a source-level verdict for the candidates in the [source search](data-source-search.md), including the separately listed CooperBench variants, plus an additional merge-resolution corpus checked for role fit. Inspection depth varies and is stated below. This is not an exhaustive validation of every row or a source-wide quality estimate. Opus 5.5 reviewed the evidence at high effort; its requested text corrections are incorporated.

## Overall verdict

**ParallACT is the recommended technical source for a controlled benchmark pilot, conditional on preserving the exact run exports, establishing reuse terms and checking broader coverage and execution provenance.** Six selected pairs applied to complete verified source trees and produced repeatable Git labels. Five run exports were not retained as bytes, so this audit is not a durable imported dataset. It justifies a small importer pilot, not a representative training dataset or a claim about natural historical dispatch.

**Do not combine every source into one dataset.** The inspected CooperBench outputs belong to a planned, communicating condition. The single-agent corpora have not yielded verified distinct-task pairs at the same base. Natural workflow sources expose some evidence, including authenticated public artifacts, but none of the checked cases supplies a complete historical coding-task pair.

There is no need to generate new agent outputs immediately to prove the replay method. If ParallACT cannot be used or lacks enough independent examples, new controlled collection remains the fallback. No model or new agent dataset was generated during this audit.

## Audit criteria

These criteria were recorded before this audit: access and declared reuse terms; actual initial input; pinned repository state; agent-output provenance; distinct-task pairing; interaction condition; reproducible Git labels; leakage risks; and usable coverage. Missing, inaccessible and not checked remain separate from verified absence. Gold patches are not agent outputs, and repeated attempts are not distinct tasks. Controlled benchmark evidence does not retrospectively pass the [AIDev pilot](../pilot/results.md).

Verdicts distinguish conditional controlled import, separate secondary use, not ready because specified checks remain unverified, and insufficient accessible evidence. A verdict concerns the examined evidence and intended use, not every row or all possible access methods.

## Complete-tree replay evidence

The audit selected the lexically first seed in each of two ParallACT families for NodeBB, Ansible and Element Web from the pinned source manifest. This is a deliberate coverage sample, not a random prevalence sample. The NodeBB contradictory run had already been fetched and its conflict label was known; NodeBB was included in the repository set because of that earlier case. The other five runs were fetched after selection. The lexical rule fixed which seed was chosen within each repository and family, but the overall selection was not blind. No missing case was replaced. The cached NodeBB case is one of the six, not a seventh independent pair. [Selection record](../../data/source-audit/benchmarks/selection.json)

| Selected ParallACT case | Reproduced Git result | Match to exported status |
| --- | --- | --- |
| NodeBB complementary `04998908` | Clean | Yes |
| Ansible complementary `5e369604` | Conflict | Yes |
| Element Web complementary `5e8488c2` | Clean | Yes |
| NodeBB contradictory `4327a09d` | Conflict | Yes |
| Ansible contradictory `1ee70fc2` | Conflict | Yes |
| Element Web contradictory `33299af5` | Conflict | Yes |

All six exports have no messages and identify the parallel-unaware condition. Each exported prompt contains its matching seed statement once; each output differs from the corresponding reference solution. These checks support the controlled run association, not the exact executed runner revision or natural task readiness. They also show why the family name must not be substituted for a Git label: a complementary case can still conflict textually.

For each case, the script downloaded a bounded source archive and built a Git index directly from blobs and modes, including symlink target bytes without following links. Before any label, the reconstructed full tree had to equal the commit tree SHA returned by the pinned upstream GitHub commit API. Two Ansible archives omitted tracked files; they initially received no label. Complete recursive tree metadata identified the missing entries. Supplemental blobs were fetched, checked against their Git hashes and sizes, and added before requiring exact tree equality. Gitlinks or changed archive entries would fail this repair. LFS payloads were not validated; a limited pointer scan found none in archive files examined by that scan.

Each agent patch was applied separately to that verified base index. The script created two synthetic local commits with a common synthetic parent representing the exact source tree, then ran Git 2.43.0 `merge-tree --write-tree` twice. The output and result tree IDs matched on repetition. These labels describe the released patches on the declared source content; the synthetic commit IDs are not the original agent heads. No repository code, hooks, filters, builds or functional tests were executed. A clean Git merge does not prove functional compatibility.

The CooperBench Outlines task1371 feature1/feature2 Claude pair also replayed cleanly on its complete verified tree, matching the exported clean status. The earlier suspicion that overlapping registry additions implied a textual conflict was not confirmed by replay. Its evaluation tests failed in the released report, illustrating that textual mergeability and behavior are different targets. The plan-sharing and communication limitations still exclude this sample from an unaware-agent dataset. [CooperBench replay](../../data/source-audit/benchmarks/cached-cooperbench.json)

## Declared reuse terms

ParallACT's checked data repository did not establish separate dataset/run-output terms. The run exports are hosted on the project site whose footer declares CC BY-SA 4.0; the scope of that declaration over those files has not been established and is an open check, not an exclusion. The [project page](https://lingyunxiao18.github.io/ParallACT/) also explicitly describes its use of SWE-Bench Pro source tasks, so the upstream task-statement terms are part of the provenance and terms chain still to check. The paper's arXiv license concerns another asset. None of this is a conclusion that research use is forbidden. The NodeBB license was independently checked at the actual run base `754965b572f33bfd864e98e4805e1182c1960080`; the earlier access note had mistaken an instance-ID suffix for that base. CooperBench's pinned trajectory card declares MIT; the inspected Outlines base declares Apache-2.0. The upstream declarations for every replayed base are retained in [upstream-declarations.json](../../data/source-audit/benchmarks/upstream-declarations.json). These facts do not decide rights for every embedded prompt or generated patch.

The practical condition is to establish the terms for the intended import and any redistribution rather than relabel all upstream code with the dataset card's license. Do not silently treat public availability, a website footer or a missing license file as a complete answer. This audit does not give a legal opinion.

## Reproducibility and limits

The [replay helper](../../scripts/audit_benchmark_sources.py) and [per-case evidence](../../data/source-audit/benchmarks/) record URLs, hashes, exact tree IDs, patch hashes, synthetic heads and merge output. The archive and supplemental source response bodies delivered to the helper totaled 54,973,285 bytes within a 256 MiB body budget. This excludes protocol overhead and separate metadata/trajectory reads and is not a total network measurement. Source caches remain outside the project. [Download ledger](../../data/source-audit/benchmarks/download-ledger.json)

Five of the six ParallACT compressed run exports were downloaded into memory, hashed, then discarded. Their hashes and mutable github.io URLs survive, but not the bytes containing the initial prompts and agent patches. The decompressed NodeBB export and some earlier records are only in `/tmp`. A hash can detect changed input but cannot recover missing input. Therefore these labels can be independently re-derived only while the source serves the same bytes, or from a preserved matching copy. Archiving the exact exports and checking their recorded hashes must be the importer's first step. No retained-evidence or dataset-readiness claim should imply that this has already happened.

The original and repair wrappers used self-terminating 40- and 35-minute deadlines with finite request/subprocess timeouts. Only unverified cases were retried, after identifying the archive omission. The second pass did not rerun completed labels. Original wrapper text and logs are retained in [execution.json](../../data/source-audit/benchmarks/execution.json). The helper evolved between collection and repair, and collection-time script hashes were not recorded; the retained current hash must not be presented as the exact code version for every earlier case. The coordinator corrected a supplemental-file URL overwriting archive provenance, added fail-closed replay guards, and preserved labels and original URL corrections in evidence. Two small code tests passed after these changes; they check archive rejection and replay handling, not model performance or all-source validity.

## Recommended next move

Use a separately specified controlled-benchmark importer pilot for ParallACT once intended reuse terms are established. First preserve the exact run exports and verify them against the recorded hashes; if they differ, do not silently reuse the old labels. Preserve exact initial prompts and base content; exclude family, mutex/shared-artifact hints, explanations, reference/test/reconciliation patches, pass/fail lists and evaluator fields from predictors. Group related seeds, generated variants, tasks and repeated runs together, with repository-held-out evaluation where coverage allows. Inspect more sources and independent cases before making a training-set or class-balance claim.

Keep CooperBench planned/communicating runs as a distinct secondary condition. Defer large single-agent corpus downloads until the record service or another bounded access path can verify joins and compatible pairs. Do not call the AIDev pilot invalid or use this benchmark replay to pass its historical gate.

If ParallACT's terms, provenance or coverage are inadequate, generate a small controlled collection using appropriately sourced tasks and capture both instructions, the exact clean checkout, dispatch, outputs and interaction policy from the start. That is the fallback after this audit, not evidence that all existing public data is unusable.
