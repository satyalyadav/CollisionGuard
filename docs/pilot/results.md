# Data-feasibility pilot results

**Decision: NOT_ASSESSABLE; do not expand or train.** The required primary evidence was not queried: historical task wording, readiness and execution records, pre-start repository snapshots, and original agent-run output heads. The pilot completed candidate selection, source-table inspection, and exploratory current-head diagnostics, but it did not complete the primary evidence collection. No pair is verified; this is not evidence that valid pairs do not exist. Git transfer caps limited only the secondary diagnostics and do not determine the strict gate.

## Sample and evidence

The complete issue-linked co-active frame contained 1,471,903 pairs. The seeded, capped sample contains 20 pairs in 12 repositories, with no repeated PR and no shared linked issue. Seventeen pairs have the same retrospective source agent label and three have different labels. The source PR windows are retrospective and do not establish concurrent execution. The selection, IDs, issue sets, visitation order, Python version, and timing are in [sample.json](../../data/pilot/sample.json). The sample froze at 2026-11-08 04:39:13 UTC before GitHub outcome collection, under protocol v2 SHA-256 `13ebc4e1bd792dc7236ff4cd60cf35254c38107fd02500a083d770bbd543abb6`. The first 10,519 bytes of the retained protocol match that hash exactly. The 1,259-byte "Evidence references and access limits" section was a post-freeze addendum written at 04:39:18 UTC. The full document hashes to `d5ee70877055b03bfadf09220ca08332bf03ac51d4c087974ae39e1b9d27fca7`. The coordinator and Opus independently verified the prefix relation. The sampling, target, validity, and budget rules did not change after sample freeze. The frozen time strings use the original host time zone; future sampling now uses UTC.

The source is AIDev revision `b8dc67df93e7c11f6f20c84129db7232eb1ec253`. [sources.json](../../data/pilot/sources.json) records the three URLs, SHA-256 hashes, sizes, and retrieval records. The three files finished downloading before selection. There are 54 issue-link entries across the selected PRs; all have issue table rows. Each [pair record](../../data/pilot/pairs/) identifies the issues, link sources, source revision, and a hash of the source title/body, without redistributing the text. Link timing, historical wording, pre-start task association, and original dispatch and output events remain unknown. The issue table does not contain edit history and the link table does not date the association. We did not check complete edit histories or original dispatch records for each pair; no conclusion about their existence follows from this audit. A later PR-to-issue link can associate an outcome retrospectively but is not a pre-start feature.

The selection funnel starts with 361,296 AIDev-pop PR rows. Joining distinct issue-linked PR IDs retains 70,335 rows; timestamp validity retains all 70,335, and nonempty clipped windows retain 70,334. The overlap and disjoint-issue pair query yields the 1,471,903-pair frame, from which the fixed sampling rules selected 20 pairs. These row counts were recomputed after review from the same pinned cached tables with one DuckDB thread and a 256 MB limit; they did not influence the frozen sample. All 20 received current PR metadata, but none received the complete historical primary-evidence audit.

Current GitHub metadata returned fixed heads for all 20 pairs. These are secondary diagnostics, not original-run targets. Of 20 isolated Git fetch attempts, nine stopped when their repository tunnel cap closed the connection, and 11 fetched objects. The TLS/early-EOF errors in those nine cases are effects of cap closure, not nine independent GitHub transport failures. Seven of the 11 fetched histories did not expose a common base at depth 50. Four ran `git merge-tree`; three returned clean and one returned conflict, but all four are **provisional** because shallow history cannot establish complete merge bases. They are recorded as errors, not definitive labels. Git may report non-text conflicts; the output does not establish a purely textual label. All 20 primary outcomes are unavailable. Pair files retain the heads, bases, commands, output, tree IDs where available, and reasons. No repository code, hooks, builds, or tests were executed.

## Resources and reproducibility

Parquet response bodies totaled 438,300,931 bytes; GitHub API response bodies totaled 773,318 bytes. The local Git tunnel accepted 460,800,656 encrypted bytes in both directions, including failed attempts. These figures sum to 899,874,905 bytes, but are **not a hard total-transfer measurement**: TLS/socket buffering, discarded cap-crossing chunks, HTTP headers, retransmissions, redirect bodies, interrupted-request accounting, and other transport overhead are not fully measured. Nine attempts hit their configured repository tunnel limit. The 64 MiB per-repository and 2 GiB total network limits are therefore **NOT_VERIFIED**, rather than certified by disk usage. A protocol deviation was the use of depth-50 fetches with full blobs rather than a blobless strategy. This likely contributed to cap exhaustion; no comparison was run to measure that effect. The retained collector still needs an explicit blob-retrieval strategy before future Git collection. Raw parquet, candidate frame and temporary Git objects were kept outside the repository. Dependency installation is separate: uv reported a 19.5 MiB DuckDB wheel download; total dependency transfer was not measured.

DuckDB used one thread and a 256 MB limit. The first sampler was stopped under memory pressure before freezing a sample; the replacement streamed pair IDs to disk. A subsequent attempt failed because DuckDB tried to import `pytz`; casting timestamps to strings fixed it. Both failures and job ownership/deadlines are in [job.log](../../data/pilot/job.log). Successful data and audit jobs ran from 04:33:52 to 04:42:54 UTC, including the two failed attempts and short gaps. Manual recovery stayed below six hours.

The records were produced by evolving earlier script revisions whose complete source and hashes were not retained. The present `pilot.py` includes later changes and must not be presented as the exact collection version. This limits exact reproduction of the historical execution. Original wrapper text and the temporary evidence note are preserved in [execution-notes.md](execution-notes.md).

At approximately 04:43:35 UTC, an inline edit added the summarizer and manually corrected the source manifest's recorded timestamps, followed by `python scripts/pilot.py summarize`. It does not implement authenticated edit-history or original dispatch/run-record collection, so running it again does not complete the primary audit.

## Review corrections

Opus 5.5 reviewed the protocol and the final evidence at high effort. The coordinator corrected the code and records afterward; those corrections were verified locally rather than through a second Opus review. Each pair's provenance now says `not_checked`, with the earlier explanations retained in a correction annotation. Recorded Git command outputs were not changed. The corrected gate treats unchecked primary evidence as incomplete even when every secondary fetch finishes.

Future cached-sample reuse checks protocol and source hashes. The one verified post-freeze reference addendum is explicitly allowed; unrelated changes fail closed. Summary and future collection records capture script hashes. Repository cap closures are separate from transport failures, retry failure counts persist, rate-limit responses pause collection, and primary replay checks require the verified base and matching repeated tree IDs. Git initialization uses an empty template, and proxy-bypass environment variables are removed. These changes do not retroactively certify historical network budgets or script provenance.

After the corrections, the local test command passed nine tests, including the regression where all primary evidence is unqueried but no Git cap is hit, changed source/protocol rejection, rate limits, repeated-tree checks, and the existing Git fixtures. No source download or Git fetch was repeated. The original six tests passed before review. Final review status is an accepted inconclusive milestone with these documented limitations, not approval of a completed primary dataset or a production-ready collector.
